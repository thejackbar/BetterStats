# Guide: BetterAdmin (Clubhouse) shell, Directory, roster, areas and roles, fees, merch and assets

**Module naming (read first).** The merged back-office module was called BetterClubhouse from v9.3.0, then renamed back to **BetterAdmin** in v9.40.0 (display only). The entitlement key is `admin` (a bundle of `fees`, `comms`, `merch`, `crm`) and never changed. Code names still say Clubhouse: `BetterClubhouseLayout.jsx`, `/admin/clubhouse/*` URLs, `pages/admin/clubhouse/`, `docs/design_handoff_betterclubhouse/`. Do not "fix" those. A club reads "BetterAdmin" everywhere; `auth/modules.py::BILLABLE_MODULE_NAMES` and `module_display_name()` are the one backend place that says it. Archive headings and older bullets still say "BetterClubhouse" (see the flags).

**Read this before** (triggers):
- Editing `components/admin/ModuleLayout.jsx`, `BetterClubhouseLayout.jsx`, `components/admin/ui.jsx` (Tailwind admin kit) or `pages/admin/clubmanager/redesign/ui.jsx` (redesign kit: `SegGroup`, `HeaderSearch`, `usePref`).
- Any Clubhouse screen: Directory, Roster, Accounts, Payments, Stock, Facilities, Events, Club Diary, Committee header rows, Today, Audiences.
- `services/roster.py`, `roster_area_roles`, `roster_shifts`, `volunteer_hours`, Areas & roles, `services/roles_activities.py`.
- Fees: `services/fees.py`, `routers/fees.py`, `fee_member_seasons`, rollover, Accounts save panels, membership tier.
- `services/directory.py`, `membership_types`, `fee_members.member_category`, Families.
- Merch or assets: `services/merch.py`, `services/assets.py`, `club_assets`, `merch_assets`, Square sync.
- Symptoms: "Could not load facilities", a picker that empties itself, "undefined ×2" on a shift chip, tier reset to "Needs tier", white border on a button row.

## Standing rules

**Shell and UI kit**
1. `ModuleLayout` is the shell for every module surface. A new Clubhouse screen passes `title` and `caption` and draws no heading of its own (the header is 19px, sticky). Passing them is the whole fix for an "old-looking" editor.
2. Module switcher, account and bookmarks live in the sidebar footer, freeing the sticky header for title, caption, `?`, filters, stat readouts and one primary action. One breakpoint for the module: `lg` (1024px); below it the sidebar is a drawer.
3. Use `components/admin/ui.jsx` (Button, TextInput/Select/Field/SearchInput, FilterPill, StatCard, Badge, Chip, Drawer, Toast, Note...) instead of a local copy. Mono is for labels and figures only, never buttons, headings or body. Text on an accent fill is `ON_ACCENT` (`#0a0d14`). Accent tints come from `TINT` (color-mix), never `rgba(var(--pb-accent-rgb), a)` (space-separated var, comma rgba cannot parse it).
4. `--pb-accent-ink` is derived from `--pb-accent` on the element it is computed on. A surface that re-points `--pb-accent` must also carry `.pb-ink` (ModuleLayout's root does).
5. Tab and filter rows wrap, they do not scroll sideways (`SegTabs` wraps). Prefer `FilterPill` over a hand-rolled tab button.
6. Segmented control chrome is `SegGroup` (container) plus `SegItem` (button), exported separately in BOTH kits. `SegButtons`/`SegTabs` are built from them. Use `SegGroup`/`SegItem` when the row is not one-of-N (Accounts' four independent filters, menus, a real `<select>`). `MenuButton` takes `seg` to wear the same style. `SegItem` takes `as` for a row whose item navigates (`aria-pressed` only on a real button).
7. The house box colour is `border-pb-hairline`. `border pb-hairline` is not a class (`pb-hairline` is a Tailwind colour); the bare form falls through to preflight `#e5e7eb` (the reported "white border"). Only `.pb-hairline-t/-b/-r` exist as real classes. `SEG_GROUP_CLS` is the one shared definition. The same typo appears about 917 times in the app and is deliberately not swept.
8. Header layout: the section's button row is centred on the title line via `ModuleLayout`'s `tabs` prop (or `HEAD_SIDE` / `HEAD_CENTRE` / `HEAD_SIDE_END` in the redesign kit): the two sides take `flex: 1 1 0` so the middle lands centred. Keep the right-hand box even when empty (zero basis costs nothing; dropping it shifts the buttons off centre). The centring wrapper must be shrinkable (never `flex-shrink: 0`): `flex-wrap` on the row cannot save a child told not to shrink.
9. Search box: one per section, below the buttons that narrow the same list, left aligned. It searches the section, not the list on screen (Facilities keeps a facility whose booking matches, Events one whose attendee matches). `EntityManager`/`AreaEditor` take `query` and narrow what is drawn, never what is loaded, so reorders still renumber against the whole list. The drag grip is withdrawn while a query runs.
10. The primary action ("+ Add person", "Publish week", "Add member", "Import bank CSV", "New product") sits on the right of the search row, not the title line. `HeaderSearch` has a `trailing` slot; `ModuleLayout` `twoRow` does the same (`items-end`). `twoRow` moves filters, bookmark and actions to a full-width second line; the filters get `flex-1 min-w-0`, the action cluster `shrink-0`. `HeaderSearch` takes a `style` escape: in a column container its `flex: 1 1 100%` reads against height, so pass `{ flex: '0 0 auto' }`.
11. Set an input width INLINE, not by class: `INPUT_CLS` carries `w-full` and which width class wins is Tailwind's emit order (intermittent 380px vs 522px).
12. Composite widgets never sit in a `<label>`. `Field` renders a `<label>`, which forwards a click on any descendant to the control it holds. Pass `composite` (renders `role="group"` div) for anything holding its own buttons (pickers, chip multiselects, segmented controls). Picker option rows and clear buttons in `clubmanager/pickers.jsx` also call `preventDefault()` in `choose()` as a net.
13. Never declare a component inside a render (`const Header = () => ...`): a new element type each render tears down the subtree and throws the caret out of an input after one character. Use a plain function and call it (`{header()}`).
14. A `const` the header reads must be declared above every `header(...)` call, including calls inside early returns (temporal dead zone; Roster's `publish`). A `data &&` guard is not a fix.
15. `usePref(key, fallback)` is the per-user, per-browser screen preference (keyed on user id). It reads in the state initialiser, not an effect, or the panel renders open for a frame. Used for the roster rail, volunteer pool and area collapse.
16. Counts come from one fetch: `pages/admin/clubhouse/data.js` `useClubhouseData` (module cache, 60s TTL) plus `deriveCounts` feed sidebar badge, Today row, Accounts KPI and Reports. Do not denormalise them.
17. Screen introductions (`clubhouse/intro.jsx`): `'always'|'once'|'never'`, per person (localStorage by user id), default `once`; Today never gets one; deep links (`navigate(to, { state: { skipIntro: true } })`) skip and mark seen; `useScreenIntro` decides once at mount in a state initialiser.
18. The indigo (`#6366F1`) is retired. `MODULE_BRAND.clubmanager` is aliased to `admin`. The four old layouts (`BetterFeesLayout` etc.) are thin wrappers over `BetterClubhouseLayout`; new screens render it directly. `BetterMerchLayout` still owns the storefront flag.
19. Row-list loads use `rows(res, ...keys)`, which always returns an array. Never chain `r?.items || r || []` (a wrong key hands the response object to `.filter` and takes the whole screen down).

**Access**
20. Give every Clubhouse nav item the capability its own router enforces (Roster `MANAGE_VOLUNTEERS`, Committee/Events `MANAGE_COMMITTEE`, Facilities `MANAGE_ASSETS`, Diary `MANAGE_CLUB_DIARY`, Families `MANAGE_FAMILIES`). Do not use a role gate (`requireRole="super_admin"`, `super: true`); the server never relied on it. `/admin/member-portal` stays super-admin-only (unlaunched, own flag).
21. BetterComms scope rule (hard): club scope reads the club's own people; Super Admin scope is BetterCricket sales telemetry. Never expose Super Admin fields, context bar or copy in a club build, not disabled, not listed. Structural: `segmentFields.jsx` exports `CLUB_FIELD_DEFS` (imported only by `ClubhouseSegments.jsx`) and `DIRECTORY_FIELD_DEFS` (imported only by `InternalSegments.jsx`). `SegmentsRoute.jsx` is the single chooser (on `is_marketing_org`, lazily). `segmentEngine.jsx` imports neither set; `defs` is a required argument (`newRule` reads the first field's first operator). Do not add an `isInternal` flag there.

**Directory and people**
22. Three independent type axes, all returned by `services/directory.list_people`: `membership_types` (migration 175, club's own catalogue, the real membership type, legitimately empty for many clubs), `fee_members.member_category` (volunteer|parent|committee|life_member|third_party|official|other), and `players.status` returned as `player_status` (NULL for a non-player, so "not playing" and "not a player" stay distinct). Do not add a single membership-type column.
23. Sponsors are not people: `org_sponsors` is the organisation. A sponsor's person is an ordinary member with the "Sponsor Contact" type. Do not union the lists.
24. Membership-type CRUD lives in BetterFees (`MANAGE_FEES`), so `GET /club-admin/directory/people` returns the catalogue itself (a committee manager would 403 elsewhere). The Directory sets `membership_type_id` through `MemberUpsert` (`_resolved_type_id`: 422 for another club's id, `""` clears). The `membership_types` join is org-scoped on both sides (`mt.organisation_id = fm.organisation_id`).
25. `typeLabel(p)` falls membership type, then category, then player/former player, then "Member". Playing and Former-player filters exclude non-players.
26. Families is BetterStats Core: `/admin/families` (`AdminFamilies`, `requireCore`, `BetterStatsLayout`). `/admin/clubhouse/directory/families` redirects to it. `BetterStatsLayout` must forward `caption`. A suggestion starts with nobody selected; opting a player in is the deliberate act and confirm is dead until someone is picked. Unselected players stay in the suggestion list (allows one surname split into two families).

**Fees**
27. Match-fee status is derived on read, never stored: `allocate_match_days(charges, match_paid)` in `services/fees.py` pays games oldest first (`played_at` nullslast, then `id`); boundary game `partial`, rest `unpaid`, $0 game `na`; leftover is credit. Buckets stay separate (match-fee credit never offsets membership owing); no tier means no credit claimed; overpayment is not clamped to 0. `paid_payment_id` and `mark-paid`/`unmark`/`payments/bulk` are legacy but live and still create `match_day` payments.
28. `patch_member_season`: key presence is intent (`model_fields_set`). Absent `fee_schedule_id` means "not editing the tier"; `null` or `""` clears it. Never assume a field is "always present" (a comment saying so wiped tiers). The fix is server-side so the Accounts list `togglePlayhq` (which sends only what it changes) needs no change.
29. Accounts detail: every save button saves every panel that has been touched (baseline compared on load), one PATCH per endpoint (Membership and Tier both write `fee_member_seasons`; two would race). A touched panel shows an UNSAVED mark; a button that writes another panel names it; two or more touched reads `SAVE ALL CHANGES (n)`; nothing edited sends nothing and says so.
30. `fee_member_seasons.playhq_registered` (+ `playhq_registered_at`, migration 235) is an admin-ticked fact (no API exposes registration). Rollover never sets it: a rolled-over row starts unticked. Reuses `PATCH .../members/{id}/season`; Accounts has a PLAYHQ column and a "Not on PlayHQ" pill (`summary.playhq_missing`).
31. Rollover: `POST /club-admin/fees/rollover/undo` clears every `FeeMemberSeason` row for a season but keeps any member with a payment (`fee_payments` cascades from `fee_member_seasons`, deleting would take real money). `DELETE /club-admin/fees/members/{member_id}/season` removes one season line, 409 once a payment exists. `POST /club-admin/fees/members/enroll` is idempotent (`members_svc.ensure_for_player`); Add member has tabs Find in club / New person. `RolloverModal` warns when the destination season has no fee schedule (tiers resolve by name against the destination rate card).
32. Accounts season is URL state (`?season=`, mirrored with `replace`); a season the club no longer holds falls back to the newest.

**Roster, areas and roles**
33. Role is a first-class level: Department, Operational Area, Role, Shift, Volunteer. An area holds a palette of roles (`roster_area_roles`, migration 306, role paired with its gating qualification `required_qualification_type_id`); each shift and pattern carries one `role_id`. The qualification gate is per role, read by `check_assignment` off the shift.
34. `roster_areas.required_role_id` and `required_qualification_type_id` are deprecated (read only by the 306 backfill; new areas leave them NULL). `list_areas` still emits the first palette entry as `required_role_id`/`_name` for stale clients. `role_id` on patterns and shifts is `ON DELETE SET NULL`; `roster_area_roles.role_id` is `NOT NULL ON DELETE CASCADE`.
35. Paid vs volunteer is derived from the shift's role type (`club_role_types.category == 'paid'`, `PAID_CATEGORY`), never a per-shift or per-person flag. `volunteer_hours.is_paid` (migration 221) is the one snapshot, stamped when hours are posted so retyping a role cannot rewrite history. A club's wage bill and volunteer effort are never summed. `role_shortages` buckets by `s.role_id` (NULL is `no_role_required`).
36. The roster subsystem is raw SQL outside ORM/alembic. Every roster DDL change is mirrored idempotently in `main.py`'s lifespan, byte-identical to the migration's statements. `volunteer_hours.roster_shift_id` has no FK on purpose (raw-SQL table, `create_all` ordering).
37. A shift outlives an archived area (`delete_area` is a soft delete, `list_areas` returns `is_active` only). Never look a shift's area up in the active-areas set: `_shift_rows` LEFT JOINs `roster_areas` and carries `area_name`; frontend `areaLabel(shift)` = `shift.area_name || areaById[..]?.name || role_name || 'Shift'`. `assign`/`check_assignment` need nothing from the area (the dead `area` param was removed; `assign` refuses only "Unknown volunteer"). Fill controls gate on the shift alone.
38. Open-shift chips group by `(area_id, role_id, start, end)`, never by name and hours (merges roles; archived areas collapse under `undefined`).
39. Roster grid (Areas view): shifts group by role via `areaRoleGroups` (only roles that have shifts draw; null role is "General help", last). One role group leaves the row byte-identical (no header, no toggle); two or more draw an expanding header. `areaDayCol` is the one place a chip is drawn, so select, drop and warn behave identically. Collapse is `usePref('roster_areas_collapsed', {})`, default expanded.
40. Confirm roster ("Confirm" is the name in code, routes and `roster_weeks.status`). `roster_shifts.worked_hours` NULL means not checked, `0` means did not turn up. Confirming reconciles (never appends): `uq_volunteer_hours_shift` makes it an upsert and deletes the posted row for a shift since unassigned or checked to zero. Unconfirming leaves posted hours alone.
41. `roster.hours_summary(start, end)` returns rostered (from `roster_shifts`) and worked (from `volunteer_hours`) as separate volunteer and paid figures; Hours tab spans week/month/season (Jul-Jun). Shift CRUD (`create_shift/update_shift/delete_shift`) is for the shift a pattern should not carry. Availability is stored as Monday=0 indexes but read tolerantly (`day_index()` accepts `'Monday'`, `'mon'`, `'0'`, `0`).
42. Roster drags: a shift drops only in its own day column (other days do not `preventDefault`, so the cursor refuses); a blocked person still accepts the drop and the server returns the sentence. Open chips are drop targets in People view. The frozen first column is `position: sticky` on the grid item; its opaque background must not be overridden by a row tint (open-shifts row layers amber via `backgroundImage`).
43. Role names are unique across every role. The Roles list hides committee roles (`is_committee` or committee-category type). `_role_clash_message(title, existing, existing_type, *, caller_is_committee)` in `services/roles_activities.py` is the one definition, used by `create_role` and `update_role`: a clash with a hidden committee role names the Committee screen and asks for a different name (never "reclassify it": the flag alone hides it). Archived clash reactivates.
44. `organisations.diary_start_month` (1-12, default 7) drives the Club Diary season plan (`monthDefs`); edited in Clubhouse Settings (`DiaryYearPanel`).

**Merch and assets**
45. One asset register: `club_assets` is the base (`merch_assets` is a strict column subset). `merch_assets` is left in place, read by nothing, its routes deleted (a second live register would drift). `services/asset_register_ddl.py` is the one DDL copy (alembic 279 and lifespan), run after both tables exist. The carry fills, never clobbers (`COALESCE(here, coming)`), matches by asset tag then case-folded name and nothing fuzzier, `DISTINCT ON` one merch row per club row, maps vocabularies (`new`->`excellent`, `retired`->`unserviceable`, `out_for_repair`->`in_repair`), appends a differing merch note. `merch_asset_id` makes the carry idempotent; `source='merch'` marks only inserted rows, so the downgrade removes only those (never delete on the id).
46. Asset alerts are core, not module-gated: `assets.asset_alerts` and `GET /club-admin/assets/alerts` (service due and `replace_due_date`). Not built: depreciation, useful life, written-down value, disposal, insurance, total asset value.
47. BetterMerch: stock lives on `merch_variants.quantity` (one 'Standard' variant for un-varied products); `record_movement` bumps balance and writes the audit row with no commit; alerts (`merch_alerts`) computed on read and feed the notification bell when `org_has_module(club,'merch')`. Gated `require_module("merch")` + `MANAGE_MERCH`. Player link is admin-only (`PlayerMerchPanel`, never on public profile). Per-variant `unit_cost`/`unit_price` override the product default; `for_resale` false means club-use (no sell price, no owing, sold/issued dropped, margin counts priced items only). `merch_categories` is a self-referencing tree (max 3 levels) per club by fixed `top_category`; delete reparents children.
48. Square is a one-way mirror, Square to BetterMerch. Sync runs catalog upsert, sales import, inventory reconcile in ONE transaction (helpers `flush`; avoids `MissingGreenlet`). Inventory count is the source of truth: sales import as `sold` movements, then a `stocktake` movement sets the absolute count (no double decrement); dedupe on `external_ref` (`square:{order_id}:{line_uid}`). `ensure_fresh_token` refreshes within a week of the 30-day expiry (`session.refresh(conn)` after). OAuth `state` is a signed JWT (`sign_square_state`, 20 min); callback is the public `routers/public_square.py`. `sync_all_square` runs daily 04:00.

## Traps and failure signatures
- "Could not load facilities." for every club: a mis-read response key, not a backend fault (rule 19).
- Picker shows empty after choosing, on Edge/Safari only, works on Chrome: composite widget inside a `<label>` (rules 12). Race: fine if the re-render is deferred a task, wiped if synchronous or in a microtask.
- Caret jumps out of a search box after one character: component declared inside a render (rule 13). `fill()` cannot catch it; type character by character and re-read `document.activeElement`.
- Button row or box has a pale `#e5e7eb` edge: `border pb-hairline` typo (rule 7). Assert the computed colour, not "has a border".
- Membership save resets tier to "Needs tier": absent key read as clear (rule 28). Two panels edited, one lost: per-button saves (rule 29).
- Roster chip reads "undefined ×2": archived-area shift looked up in the active set (rule 37). React renders a bare `undefined` child as empty; only string concat prints the word, so a reproduction needs a pair.
- "Can't roster X here. Unknown volunteer or area" on a shift of an archived area: stale area guard (rule 37).
- Adding a role "already exists" with none visible: hidden committee role (rule 43).
- Match Day roles merged into one chip or one grid row: grouping by name not ids (rules 38, 39).
- Header search box takes the whole line inside a column, or a button lands after CLEAR instead of the right: `HeaderSearch` `style` and `alignSelf: 'stretch'` (rule 10). Committee's readouts need the action removed from the header (both carry `marginLeft: 'auto'` and share the space).
- Centred button row pushes the page sideways at 390px: `flex-shrink: 0` on the centring wrapper (rule 8).
- Infinite request loop (60+ calls to `/fees/all-members`): an effect lists `toast` as a dependency and its `catch` raises a toast. Watch this shape anywhere.
- Unrelated PATCH 500s in a stubbed-lifespan harness: missing `audit_logs` (aborted transaction poisons the caller's commit). `player_achievements`, `org_award_definitions`, `audit_logs` are lifespan-created and must be created by hand.
- Asset carry downgrade deleted the club's own assets: it deleted on `merch_asset_id` instead of `source='merch'` (rule 45).
- A stub returning `{seasons: [...]}` where a router returns a bare array makes Accounts/Payments throw on `.filter`; overflow baselines taken from that page are wrong. Check the real shape first.
- Measure the rendered page before theorising about design differences (the Directory vs editors gap was heading size 24px vs 19px, non-wrapping tabs, mono body copy and mono uppercase buttons, not the typeface).

## How to verify a change here
- Backend (real Postgres, shipped route bodies): `backend/verification/verify_roster_area_roles.py` (control with the feature reverted fails per-role qualification and role-on-shift checks; also an archived-area case), `verify_role_create_committee_clash.py` (control: committee-aware branch of `_role_clash_message` neutered, checks that name the Committee screen fail), `verify_member_fees_form_save.py` (control: previous commit fails the tier-reset case; harness must expire the session after a raw UPDATE).
- Browser (Chromium, API stubbed at network layer): `frontend/verification/verify_clubhouse_buttons_browser.mjs` (button-row box read off computed style, centring within 24px of header midpoint, search below caption and left-aligned with header, action on the search line, caret held per character; control fails most), `verify_member_fees_save_browser.mjs`, `verify_roster_area_roles_browser.mjs`, `verify_roster_role_grid_browser.mjs`, `verify_roster_open_shift_labels_browser.mjs` (target `div[draggable]`, the chip with the handler). Also `verify_roster_*_browser.mjs` siblings for shift ops and scroll regions.
- Measurement checks must be real: assert "one line" by vertical overlap of the two real boxes, "below" by measuring boxes, colours by computed style. Gate collapse/absence checks on the thing having been shown first, or a build that never draws it passes vacuously.
- A control run must report, not crash: read new keys with `.get`, wrap the call in a no-arg factory (`caught(label, lambda: ...)`), use `seen`/`press`/`pick`/`opts` helpers that report absence. Guard a whole block, not each read, when the block assumes a form exists.
- `text=UNSAVED` matches ancestors too; use `data-testid`. Filter `/usage/` page-view telemetry out of "save" counts.
- HTML5 drag tests: Playwright's mouse hangs in Chromium's native drag; dispatch `DragEvent`s, `dragstart` and `drop` in separate `evaluate` calls.
- A screenshot pass of all Clubhouse screens at 390px asserting each `<h1>` computed font, size, weight and `documentElement.scrollWidth > clientWidth` is worth repeating when a screen is added. Three screens overflow at 390px pre-existing (Accounts, Payments "Import bank CSV", Stock "New product"); the suite budgets the measured numbers.
- The suites share one database; stub tables from another suite can collide. Run a suite whose stubs differ on its own database.
