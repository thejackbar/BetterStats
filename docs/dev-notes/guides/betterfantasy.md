# BetterFantasyCricket (club fantasy competition)

Code: `backend/app/services/fantasy_engine.py` (rounds, pool, settlement), `fantasy_squad.py`, `fantasy_draft.py`, `routers/fantasy.py` (club admin), `routers/public_fantasy.py` (member play), `frontend/src/pages/admin/fantasy`, `frontend/src/pages/fantasy`. Checks: `backend/verification/verify_fantasy_rounds.py`, `verify_fantasy_unsettle.py`.

- A round's `status` is `upcoming | scored | unsettled`. `unsettled` means an admin took an ended round back out of settlement. Every public read treats it as not scored; the nightly job and Settle due rounds skip it (`fantasy_engine.AUTO_SETTLE_SKIP`). Use that tuple, never a bare `!= "scored"`, for anything that settles unattended.
- `settle_round` writes player scores, pool totals, squad round rows, season totals, head-to-head results, the free-transfer rollover and the status. `unsettle_round` must undo each. Add a line there when settlement starts writing something new.
- A squad's round row also holds what the manager did before lock (`chip_used`, `transfers_made`, `transfer_hit`). Unsettle keeps any row with those and only clears scoring. Never delete such a row.
- `refresh_live_round` writes provisional player, squad and ladder rows for a running round, so a long round shows points. It must never grant the rollover, fill head-to-head results or mark the round scored. Anything shown as "live" that adds a round's points to `squad.total_points` has to swap out the stored provisional figure first, or it counts twice.
- The free-transfer rollover is not idempotent: re-settling an already scored round banks another one. Unsettle takes one back (floored at 0, squads holding a wildcard or free hit left alone).
- Super admin entry: Better HQ > Clubs & Data > Fantasy Competitions (`/admin/super/fantasy`). Open uses `switchClub(clubId, 'admin/fantasy')`.
- Admin "view as a team": `POST /club-admin/fantasy/view-as` sets a separate 3 hour cookie (`bs_fantasy_viewas`, a JWT with `typ: fantasy_viewas`) that `public_fantasy._read_session` honours ahead of the member's own cookie. It is read only through ONE router dependency, `_block_writes_while_viewing`; any new public write is covered automatically, so never add a write route outside that router. Only paths containing `/view-as/` (switch, exit) pass the guard. Never mint a member session for the admin: it would overwrite a real manager's sign-in.
- Every table with a player FK is `ON DELETE CASCADE` or `SET NULL`, so each must be on `merge_carry.CARRIED` (the Fantasy ones are, with club guards). A new fantasy table that points at a player goes on that list in the same change. `fantasy_merge_repair` restores picks lost before that fix from the stored lineup snapshots, which is why unsettling (which clears a kept row's lineup) is also the end of that evidence.
- A hand-typed round score is a `fantasy_player_round_scores` row with `breakdown.manual` set. Settle, the live refresh and unsettle must never overwrite or delete it; only `clear_manual_score` does. Admin pick edits (`add_squad_player`) warn on size and quota, never refuse, and re-score from a chosen round through `fantasy_engine.rescore_from_round`.
- `settle_round` banks the free transfer only when the round was not already scored (`first_settle`), so re-settling is safe.
- Deleted Fantasy picks can be read back from the live table until VACUUM clears them: `fantasy_merge_repair.read_deleted_picks` (pageinspect, superuser, read only) behind `restore_fantasy_merged_picks --from-dead-rows`. Do it soon after the loss and never run VACUUM FULL first. Backups are age-encrypted and the key is not kept on the server, so a backup route needs someone who holds the key.
- Hand-added pool players ("Add new player") have no games; their twin with games is found by `fantasy_pool_check` (sorted-words name key, so "Taylor, Ashton" matches "Ashton Taylor") and merged from `HandAddedPlayersCard` via `POST /season/{id}/merge-player`. That route accepts only a pair the list shows, needs MANAGE_MERGES as well as MANAGE_FANTASY, runs the normal `_merge_players_core` and then re-scores from round 1. `verify_fantasy_player_merge.py` section 13 seeds a player into every Fantasy table that has a player FK (read from `pg_constraint`) and fails if a new one is not on `merge_carry.CARRIED`.
