# Guide: BetterAdmin (Clubhouse) Committee, meeting room, minutes and strategic plans

**Naming note first.** The module a club reads as **BetterAdmin** is still keyed `admin` in code, billing and entitlement. Its code, URLs and files still say "clubhouse": `BetterClubhouseLayout.jsx`, `/admin/clubhouse/*`, `pages/admin/clubhouse/`, `redesign/screens/Committee.jsx`. The name was BetterAdmin, then BetterClubhouse (v9.3.0 merge), then BetterAdmin again (v9.40.0, display only). Archive headings from v9.3 to v9.7 say "BetterClubhouse". Treat them as the same module. Never show "BetterClubhouse" to a person.

**Read this before**:
- Touching `frontend/src/pages/admin/clubmanager/redesign/screens/Committee.jsx`, `pages/admin/MeetingRoom.jsx`, `components/admin/clubmanager/governance.jsx`, `AdminCommittee.jsx`, `planLabels.js`, `minutesDoc.js`, `lib/textDocs.js`.

- Strategic plans, themes (pillars), objectives, actions (`committee_tasks`), motions (`meeting_motions`), agenda sections, agenda templates, attendance, minutes download (Word or PDF), committee document uploads, Office Bearer awards.
- Symptoms: caret leaves a search box after one character; meeting room runs off the right edge; a theme shows in the wrong plan; deleting a plan or theme "lost" objectives; a PDF with blank pages or huge indents; an objective picker or vote list too pale to read.

## Standing rules

**Naming and shell**
1. The rename between BetterAdmin and BetterClubhouse is DISPLAY ONLY. Entitlement, `org_module_subscriptions`, module key `admin` and every stored row are untouched. Display strings live in `MODULE_BRAND.admin.name`, `MODULE_GROUPS.admin.name`, `MODULE_TOGGLES`, `BILLABLE_MODULE_NAMES` (backend, `auth/modules.py`) and `ModuleLayout`'s `moduleName` ("Admin"). `clubhouse` stays in `moduleBrand`'s ALIAS map so old callers still work.
2. Committee's section buttons are Meetings (default), Plans, Documents, Calendar, Positions. Positions was kept although the brief did not name it: a rename does not drop a working screen. Keys live in `st` (`cteMeetingsView`, `cteActionsView`, `cteTab`), so a label can change without moving anyone's view.
3. Meetings holds All Meetings, Actions, Motions, Meeting Templates. Actions keeps its own List, Board, Timeline row. The old `Motions & Actions` tab is gone. `cteMaView` is read in exactly one place, to carry a stored `cteTab === 'motions'` onto the button it became.
4. Plans has no button row: it IS the Strategic Plans tree. `PlanTab`'s `section="themes"` and `"objectives"` branches are mounted nowhere (kept so they can come back). Do not assume anything exercises them.
5. Documents, Calendar, Plans and the Actions board/timeline are the manage screen's own components, mounted here, not copied (`TasksTab`, `DocumentsTab`, `CalendarTab` exported from `AdminCommittee.jsx`; `PlanTab` from `governance.jsx`). Load them with `lazy()`: most visits only read Meetings.
6. `TasksTab` takes optional `view`/`onView` and hides its own toggle when given; `PlanTab` takes `section` the same way. Passing nothing must leave the manage screen byte-for-byte as it was. `query` works like `view`: a caller drawing its own search box passes it and the tab stops drawing one.
7. The Committee header no longer links to `/admin/clubhouse/committee/manage` (v9.50.4). The route still exists and renders. Every editor is mounted in Committee.

**Search**
8. NEVER declare a component inside a render (`const Header = () => ...`). React sees a new element type each render and rebuilds the subtree, taking the focused input with it. Use plain functions returning elements and CALL them (`{subBar()}`). Same for `EditableHeading`: module level only.
9. One search per section, and it searches the SECTION, not the list on screen. `meetingMatches` reads agenda (title, description, outcome notes), minutes, private notes, every motion and action. `matches()` is the one case-folded rule. A section change clears the query. Positions is not searched.
10. The plan TREE narrows under a query (a branch stays if anything under it matches; `railOpenFor` opens every level while a query runs). The plan DASHBOARD does not narrow: "2 of 3 on track" filtered is a wrong number. Filtering is for drawing only: `groups`, `themesIn`, `objectiveOrder` stay whole or a reorder renumbers against a filtered list.
11. Season on All Meetings is the club's DIARY year (`organisations.diary_start_month`, read via `adminGetSettings`, which a committee manager without `MANAGE_SETTINGS` may call). Options are seasons the club met in plus the current one. `sel` reads the filtered list.

**Plan tree (migrations 230, 232, 275, 276)**
12. A plan owns its themes (`club_strategic_pillars.plan_id`), a theme owns its objectives (`club_objectives.pillar_id` and `plan_id`). `plan_id` on themes and `plan_id`/`pillar_id` on objectives are NOT NULL, and the two objective FKs are ON DELETE CASCADE (SET NULL cannot coexist with NOT NULL). No orphans are representable. Never key a branch on a plan or theme NAME: two plans may share a name.
13. `committee_tasks` and `meeting_motions` to `club_objectives` stays ON DELETE SET NULL. Deleting a plan, theme or objective never deletes an ACTION or a MOTION; they are kept and unlinked. This is the one rule not to relax. Assert the referential action, not just that a row survived.
14. A theme is created with its plan or refused; an objective with its theme or refused. `upsert_objective` takes its plan FROM its theme (a mismatched pair follows the theme). Validate BEFORE adding the row in `upsert_pillar`/`upsert_objective`: each ownership check is a SELECT, which autoflushes a half-built row with no plan and turns a 422 into a NOT NULL 500.
15. Migration 275 SPLITS a pillar whose objectives span several plans (one copy per extra plan, objectives repointed) BEFORE the claim step. Migration 276 order is load-bearing: inherit plan from theme, carrier plan `Unfiled work`, `General` theme per objective's own plan, FKs, then NOT NULLs. The one row deleted is a theme with no plan and no objectives. `services/pillar_plan_ddl.py` and `services/plan_tree_ddl.py` are the ONE copy alembic and the lifespan mirror both run; every statement is idempotent.
16. Migration 230 backfill guards with `NOT EXISTS`, NOT `ON CONFLICT`. There is deliberately no unique `(organisation_id, name)` on plans (a club may name two the same), so a conflict clause never fires and the lifespan re-run would mint plans on every boot. Backfill groups case-insensitively on trimmed name. The old `club_objectives.plan` text column is history; nothing reads it.
17. A pillar (theme) is a grouping, not a fourth level. Resist adding a level. No parent/child plans, no `horizon` enum, no `progress_source`, no `item_type` on agenda items (volunteer committees would have to answer each).
18. A committee SEAT can own an objective (`club_objectives.owner_position_id`, so ownership moves at the AGM). Write one owner (seat or named person), never both.
19. An objective carries its own `due_date`, `owner_member_id`, `budget`. `objective_progress` emits `own_budget` (the club's allocation) beside effective `budget`, else a rolled-up 0 reads as "allocated $0". A plan's figures sum its OBJECTIVES', not a second pass over actions.
20. `meeting_motions.objective_id` exists. An action raised under a motion inherits the motion's objective. An action reports `raised_meeting_id` (own meeting, else its motion's) and must not overwrite `meeting_id`.
21. A null means "clear it". `_TASK_CLEARABLE` assigns nullable action columns on key presence; routers use `exclude_unset` (a key being present IS the intent). Title, category, status, percent stay guarded (NOT NULL).
22. `plan_report` scopes motions through their MEETING's org (`meeting_motions` has no `organisation_id`). It still emits an empty `unassigned` key for a browser on an older bundle mid-deploy.
23. Seeding is skip-don't-replace at every level (`seed_starter_plan`: four pillars, a plan named for the club's diary year via `_season_label`, one example objective per pillar; `STARTER_AGENDA_TEMPLATES`: AGM and committee meeting). A blank page kills adoption. Seed on demand only.
24. Ordering: `sort_order` is stamped by POSITION over a WHOLE level (`reorder_plan_tree`; objectives are ordered club-wide and only grouped). A foreign or stale id is skipped without a gap. "+ THEME" creates then splices the new id after the selected one. A row drops only on a SIBLING (same level and branch); other dragovers do not `preventDefault`. Re-parenting is not a drag.
25. The objective PICKER (`ObjectiveSelect`, six mounts) is a tree and only LEAVES are selectable. Plan and theme rows are headings with no `role="option"`. It is not a `<select>`, so a test asserting `<option>` is asserting the old control. The Actions list "Any objective" dropdown is a FILTER, deliberately not this. `planLabels.js` names all three tiers (PLAN > THEME > OBJECTIVE); `objectiveLabel` and `objectiveTiers` are one dataset, and the module is its own file so it stays out of first paint.
26. `ActionEditor` and `MotionEditor` (governance.jsx) are the one editor each, opened from list, board, timeline and tree. `EditorShell` is a dialog over a list and plain content when `inline`. `ACTION_CATEGORIES`, `ACTION_STATUSES`, `ACTION_STATUS_LABELS` live there. A motion belongs to a MEETING: every register row carries `meeting_id` and writes to that meeting's endpoint.
27. `?cascade` is GONE from plan and theme delete (see FLAG-CTE-2). A plan delete takes its themes and objectives; a theme delete reaches only its own plan's objectives.
28. A Meeting Template may be deleted while meetings use it: `_apply_agenda_template` COPIES items at creation and `committee_meetings.agenda_template_id` is ON DELETE SET NULL. Say that in the confirm; do not warn about a loss that cannot happen.

**Plan delivery dashboard (v9.50.x)**
29. `PlanDelivery` is a dashboard, not a dump: plan figures, then what needs attention, then a row per theme; objectives inside an opened theme, work inside an opened objective. The OBJECTIVE is the unit. Rendering `DeliveryRow` uniformly at every level was the bug.
30. No single verdict at plan level (`rollUp` takes the worst underneath, which would brand a 16-objective plan LATE forever). Headline is a proportion (`n/m objectives on track`) plus a count needing attention. A group's verdict is the worst of what is under it, ignoring what cannot be judged.
31. NOT STARTED is an absence, not a severity: `rollUp` excludes it and it wins only when nothing under it has begun. When all that has begun is finished but something has not, the group reads ON TRACK, not DONE.
32. Silence where the data cannot answer: no start AND due date means no schedule verdict and no tick; nothing allocated means no budget verdict; a motion gets an outcome and no meters. `NO DATES` is muted metadata, not a chip.
33. Every state is a word plus a glyph (`StateChip`: DONE, ON TRACK, BEHIND, LATE, NO DATES, OVER BUDGET, SPENDING AHEAD, IN BUDGET). Measured: green/amber separate by only 7.2 delta E under protanopia and red/amber by 14 in light theme, so never distinguish a state by colour alone.
34. Progress is a meter with a target tick (schedule: share of the action's span elapsed; budget: share of work done). Both run 0 to 100. Never a second axis. The tick shows only on action detail; scanning surfaces write the variance (`18% behind`, `spending ahead`). `DRIFT_TOLERANCE` (10) and `SPEND_TOLERANCE` (15) are deliberate choices.
35. Summarise the plan ONCE (`PlanFigures` inside the plan pane's title card). A second card printed 44% and 45% an inch apart. Any number of themes may be open (`openThemes` is a Set; `jumpTo` unions). The rail folds away rather than becoming tabs.
36. Tree geometry: `TREE_STEP` (`ml-[34px]`) is derived from `TWISTY_BOX` (28px) plus the row gap, so a child's caret sits under the parent label's first letter; change one and the other moves. `Twisty` IS the 28x28 button (it was a 5.5 x 24px hit area). One-line rows are 37px. Level rails use `color-mix`, never `${accent}66` (accent is a `var()`, so the border vanishes). `LEVEL` sets per-depth shade.

**Agenda sections (migration 231)**
37. `meeting_agenda_items.section` is a LABEL, not a table. The agenda stays one ordered sequence. `reorder_agenda_items` takes optional `sections` parallel to `ids`, in ONE write; a mismatched pair is ignored. It ignores ids not in the meeting (list comes from a browser). A dragged item adopts the section it lands among; a new item joins the section the agenda ends in. A section repeated in two runs draws its heading twice (never sort behind the club's back). `agenda_templates.items` is JSONB `{section, title, description}`, no migration.

**Meeting room**
38. One room, mounted twice: `MeetingRoomPanel` (no chrome) inside Committee, and the default export as a thin route wrapper at `/admin/clubhouse/committee/meeting/:meetingId`. The standalone page must stay as it was (OPEN MEETING on the manage screen and bookmarks go there). The panel hands `{ meeting, setStatus, setTitle, reload }` up through `onMeta`; embedded, `inlineHeader` draws the header with Close. Room is open only on the SELECTED meeting (`room = st.cteRoom === sel.id ? sel.id : null`). `refreshMeeting` re-reads one meeting on exit only.
39. `chip(C.accent)` fails in this screen: `chip` builds `${fg}66` and `C.accent` is `var(--pb-accent)`. `openChip` uses `color-mix` for the edge and `--pb-accent-ink` for text.
40. `GET .../meetings/{id}/room` is one fetch for the whole screen (meeting, agenda, motions with votes, actions, attendance, pool, `next_meeting`). Everything saves as it happens; free text via `useAutosave` (700ms debounce). A completed meeting opens the same screen; nothing is read-only.
41. Attendance starts from committee-term holders (`meeting_attendee_pool` flags and sorts them first). Only people marked present can vote or take an action: a UI rule only, `set_motion_votes` accepts any member (a phone vote is real). `previous_meeting_attendance` walks back up to 10 meetings of the SAME type, skips one with nobody present, carries only `present` (never apologies), and the button shows only while attendance is empty.
42. `assigned_to_member_id` stays the primary owner. `set_task_assignees` writes the join table (`committee_task_assignees`, migration 220) AND sets that column to the first id; never drop the column. `load_task_assignees` falls back to it for pre-220 actions.
43. A motion is a record first, a form second: the row shows wording, tally, objective; OUTCOME is the one live control. Edit closes with `Done`, not Save/Cancel (votes write as cast). Click on a record opens it but the record is deliberately NOT `role="button"` (giant accessible name, broke picker tests); outcome select, drag handle and Done `stopPropagation`.
44. The button that finishes a record must not carry the name of the one that opened it: `+ Add motion` opens, `RECORD MOTION` / `RECORD ACTION` finish; Enter finishes (Shift+Enter newline for wording, Escape backs out).
45. `MotionForm` is the one definition, mounted by `+ Add motion` and by Edit, with a `live` flag: an existing motion saves as pressed; a new one is held until `RECORD MOTION`. Call `useAutosave` every render so hook order cannot change. Named votes are a second request (they key on the motion id): `create_motion` takes `outcome`, tallies and `notes` so the rest lands in ONE write. Movers are picked from people in the room, but an already-recorded name stays selectable. Draw the `moved by ... seconded by ...` line only when one is set.
46. A division (per-person votes) sits behind `+ Record a division`, seeded OPEN when the motion already has names. Tallies derive from names when recorded; an outcome alone is a complete voice vote. `All present: For` writes For for everyone in one click.
47. An action can be due back at the next meeting: it fills the REAL date (`next_meeting_after`: prefers next meeting of the same kind, falls back to any, skips cancelled). Button names the date, hidden if none later.
48. Motions drag two ways: one `drag` ref with `kind: 'item' | 'motion'`. Motions are ordered across the whole MEETING but dragged within an item, so `motionOrderAfter` splices the within-item move back into the meeting-wide sequence. The motion handle calls `stopPropagation` on `onDragStart`.
49. Layout: room grid is `xl:grid-cols-[minmax(0,1fr)_320px]`, never bare `1fr` (a track's automatic minimum is its content). Every level between long text and the scroll container needs `min-width: 0`. `truncate` inside a wrapping flex row EXPANDS it; breadcrumbs wrap (the objective is the tail, so an ellipsis hides the part that matters). No box inside a box: a motion and an action are a tinted left edge, only the agenda item is a full container. `WHAT WAS SAID` is `rows={10}`.
50. Legibility: in the meeting room, `ObjectiveSelect` and vote lists, paint nothing at `--pb-faintest` (1.64:1) or `--pb-faint` (2.75:1). `cap` is `text-pb-dim` (5.40:1). The tokens themselves are unchanged (faintest is still right for a rule or a disabled state).
51. `EditableHeading` (exported from `MeetingRoom.jsx`) renames a meeting in the summary `<h2>` and the room header. Enter saves, Escape reverts and sends nothing, a BLANK name is refused. The standalone route is deliberately NOT editable: its title is a plain string that also feeds `ModuleLayout`'s bookmark label (a node would print `[object Object]`).

**Minutes and documents**
52. Minutes downloads are written IN THE BROWSER from the textarea ref (`downloadField`), never fetched from the record: autosave is a 700ms debounce and a fast download would miss the last sentence. `lib/textDocs.js` has no dependency (docx = stored, not deflated, zip; PDF = objects plus xref). `minutesTyped` and `notesTyped` start `null` = "untouched" and fall back to the record; typing and `draft()` set them. Buttons are disabled (not hidden) on an empty field, with a title saying why. The notes file says it is not part of the minutes.
53. The minutes document is composed from the RECORD, not the narrative: `minutesDoc.buildMinutesDoc` builds details table, agenda, numbered section per item, each item's motions and actions, motions summary (`M-01` numbering in document order, same number on the motion's own block) and actions table. `splitNarrative` returns `loose` as well as `sections`; anything not under a heading, or under a heading no agenda item claims, goes to `Record of Discussion` (else typed prose is lost). A bare line matching an agenda item's title is a heading; a short run of short lines before the first heading is dropped as model preamble. `textDocs` takes BLOCKS (title, heading, para, label, bullets, table, spacer); `body` still works for plain text (private notes).
54. `draft_minutes` context (`_minutes_context`) nests each motion and action UNDER its agenda item with objective breadcrumb, tally and named votes, and the prompt says to write a motion under the item it is listed against. A flat list made the model file a motion under the wrong item. Draft is returned, never saved (secretary decides).
55. PDF specifics: `indent` is TWIPS in Word; `pdfIndent` converts to points, `indentPt` overrides where the formats deliberately differ. Fonts `/Arial` and `/Arial,Bold` are declared TrueType with FontDescriptor and Widths, nothing embedded; declared Widths are the ones layout measured with. Helvetica-Bold has its own width table (not regular x 1.06). PDF is WinAnsi (curly quotes and dashes mapped 0x80 to 0x9F; unmappable becomes `?`); docx is UTF-8. Wrap uses real advance widths and breaks over-long words by character. `w:sz` is half-points; `w:spacing` twentieths of a point; strip control characters (Word rejects the file); Word `para()` has `w:spacing w:before` (~240 is one blank line). Blank line either side of every agenda heading and MOTION/ACTION label in both formats. Names are stored "Surname, First": join lists with semicolons. Size short table columns against the widest real value ("Not recorded", "In Progress"). A table header repeats on each page.
56. Every PDF op must report a height (`heightOf`, per kind, falls back to 0). An op with no height gave NaN, `room()` false for everything after, `y` never recovered: 19 pages, half blank, all content checks still green. `push` is variadic (`push(...tableOps(b))`).
57. Committee documents (migration 218): a row carries a `url` OR a file (`file_data`, `file_name`, `file_mime`, `file_size`, `uploaded_by_user_id`), never both. `MAX_DOCUMENT_BYTES` 15MB, `ALLOWED_DOCUMENT_MIMES` is an allowlist. `file_data` is deferred on list queries and `has_file` reads `file_size`. `organisations.committee_docs_office_bearer_only` defaults TRUE (edited via `/club-admin/settings`, `MANAGE_SETTINGS`). `services/committee.can_open_document`: uploader, current Office Bearer, or Main Admin (`club_memberships.role == 'club_admin'`, unconstrained, per direct instruction). It governs UPLOADS only; a link is a URL we do not host, so UI copy must not imply a wall. Enforcement is `GET /documents/{id}/file` (re-checks, `Cache-Control: private, no-store`); PATCH/DELETE go through `_document_writable_or_403`. `can_open` in a list is presentation only. There is no `users` to `fee_members` FK: `member_for_user` joins on lowercased email; no email means "not an office bearer". `is_office_bearer` on a position derives from the role TYPE (`_role_is_office_bearer`), resynced on each `sync_committee_positions`, with the name set as fallback for typeless roles.
58. Office Bearer awards ARE roles (`services/office_bearers.py`): award category fixed "Office Bearer", subcategory is a `club_role_types` row, achievement is a `club_roles` row, `player_achievements.club_role_id` records which. `sync_award_definitions` runs both ways and is idempotent (called from `GET /award-definitions` inside try/rollback): ADOPT from definitions AND recorded achievements, PUBLISH committee/captain/coach roles. Seeding is gated on having no ROLES (not no definitions). `SUBCATEGORY_TO_ROLE_TYPE`/`ROLE_TYPE_TO_SUBCATEGORY` map the vocabularies; `PUBLISHED_ROLE_TYPES` keeps ground staff, canteen, officials out of the awards list; `COMMITTEE_ROLE_TYPES` decides seats (a 1st XI Captain is an honour, not a seat). `ensure_role_for_award` matches on title alone (unique per org, title) and never retypes an existing role. `adopt_awards_as_terms` inserts directly (not `start_term`, which auto-closes) and is idempotent on (position, holder, start date); season becomes 1 Jul of start year to 30 Jun after end year; an award with no season is skipped. `_season_year` accepts a `seasons` UUID or a label like "2025/26".
59. `PersonSearch` (`clubmanager/pickers.jsx`): the SERVER searches, only matches return. Use it over `MemberSelect` on any picker that must offer the whole club. `GET /club-admin/fees/people/search` is `fee_members` UNION club players with no member row, org-scoped both sides, archived never offered, `needs_member: true` for the unenrolled, asks for limit+1 to say "more". Debounce 220ms, drop a response if the box moved on. `start_term` takes `player_id` and enrols via `members.ensure_for_player` (idempotent, un-archives) so it stays one request under `MANAGE_COMMITTEE`. `/fees/all-members` still means member rows for its eight callers; only CHOOSING is a search.

**Governance schema (migration 217)**
60. Tables: `club_objectives`, `committee_task_dependencies`, `meeting_motion_votes`, `committee_notes` (polymorphic: task, motion, meeting, objective). Columns on `committee_tasks` (`budget_estimate`, `actual_expenditure`, `percent_complete`, `start_date`, `objective_id`, `meeting_id`, `motion_id`, `outcome_notes`, `closed_by_member_id`), `meeting_motions` (`is_resolution`, `resolution_ref`, `resolved_at`), `committee_documents` (`entity_type`, `entity_id`). Mirrored idempotently in the `main.py` lifespan. Only a carried motion can become a resolution (`make_resolution` raises). Per-member votes RE-DERIVE the tallies; a club that counts hands stores only a count. Documents stay link-based by design (plus the 218 upload).
61. Timeline (`ActionTimeline`): ruler shares the rows' `w-[38%]` plus `flex-1` geometry; ticks snap to the 1st of the month; `chain()` needs the `walking` cycle guard (server rejects only self-dependency).
62. Owes-money audience: `owes_money` is derived, never SQL. `build_query` resolves ids via `services/fees.owing_player_ids` (the Accounts screen's `_financials`) into `player_id IN (...)`. Do not reimplement the balance in SQL.

## Traps and failure signatures
- Typing in a section search drops focus after one character: component declared in a render body (rule 8). `fill()` cannot catch it; type per character and re-read `document.activeElement`.
- A second plan shows the first plan's themes, or deleting a theme deletes another plan's objectives: club-scoped pillars (232, superseded by 275). Never fall back to "draw every club theme".
- HTTP 500 on saving a theme or objective for a foreign plan, instead of 422: autoflush of a half-built row (rule 14).
- Plans minted again on every app boot: 230 backfill guarded with `ON CONFLICT` instead of `NOT EXISTS` (rule 16).
- "Allocated $0" on an objective nobody budgeted: missing `own_budget` (rule 19).
- Action objective, budget or due date can be set but never cleared: `if fields[f] is not None` guard (rule 21).
- New field on a task or document silently ignored, plan reports 0 actions: added to migration and service but not to Pydantic `TaskCreate`/`TaskPatch`/`DocumentCreate`/`DocumentPatch`.
- `MissingGreenlet` after `commit()`: instance expired; `await db.refresh(obj)` before serialising (vote and resolution endpoints). Also on touching deferred `file_data` in a list row.
- `confdeltype` read as bytes from asyncpg: cast `confdeltype::text` or comparisons to `'c'` are quietly false.
- Meeting room and attendance rail run off the right edge: bare `1fr` grid track, or `truncate` in a wrapping flex row (rule 49). Check the EMBEDDED room inside a narrower pane, not only the standalone page.
- Accent border vanishes: `chip(C.accent)` builds `var(--pb-accent)66` (rule 39).
- Blank-looking pale text: `--pb-faintest`/`--pb-faint` on words (rule 50).
- PDF with 19 pages and half blank, all content checks green: an op with no height (rule 56). PDF indent a third of the page: twips read as points (rule 55).
- Whole account lands in one Record of Discussion lump with the model's own title block: bare-line agenda titles not treated as headings (rule 53).
- Typed minutes missing from a download: file fetched from the record instead of the box (rule 52).
- Someone on the old `Motions & Actions` tab lands on nothing: `cteMaView` carry-over (rule 3).
- Roster blank forever for a club that opened it before configuring areas: `get_or_create_week` never regenerated an empty draft week. `services/roster.py` now regenerates when `_has_shifts` is false (`_has_shifts` then `_generate_shifts`); the screen reports the real error and HTTP status. Detail belongs in the roster guide.
- Docs "orphaned": ~5,300 lines of editors (`AdminCommittee`, `AdminFamilies`, `AdminClubDiary`, `AdminAssets`, `AdminEvents`, Qualifications, Volunteers, Roles, Activities) had no route after commit `6ff23c6`. They live under `/admin/clubhouse/*/manage`. Folding CRUD into the viewers is still the end state.

## How to verify a change here
- Suites named in the archive: `frontend/verification/verify_minutes_download_browser.mjs` (minutes and notes files; control with the change stashed finds no rows and no downloads) and `frontend/verification/verify_clubhouse_buttons_browser.mjs` (button rows and search). The archive also refers to a meeting-room suite (`room.mjs`), a minutes suite (107 checks) and `check2.mjs`, and to Postgres suites for 217, 218, 220, 230 to 232, 275, 276 and `next_meeting_after`. Most of these are not in the repo under obvious names (FLAG-CTE-8). Expect to write or find a harness.
- What a control run must fail on: search focus (all five characters lose focus); meeting room 16 of 90 fail on the previous commit (box rows, 21 elements at 1.64:1, overflow); embedded room shows 282px overflow at 1440px with the fix stashed; minutes doc with the change stashed has no club heading, details table, agenda or tables; PDF typography checks fail on indent, gap before agenda title, both font names.
- Postgres checks that mattered: migration applied three times to a populated pre-migration table; alembic and lifespan mirror land on the same schema (a separate check); all five referential actions read from `pg_constraint`; action and motion outlive a whole plan unlinked; cross-club rejection of a foreign plan, pillar, position id.
- Harness gotchas: `Base.metadata.create_all` gives ORM tables only. Raw-SQL tables exist only via the lifespan, which aborts at the first failing statement, so replay `text(...)` statements from `main.py` skipping failures and stub the lifespan. Stub API shapes must match the real router (`previous_attendance` is an object or null; single-meeting GET returns the MEETING not the list) or you measure a broken page. `page.evaluate` given a STRING treats it as an expression; `\d` inside a JS template literal is `d` (write `\\d`); `getByRole` `name` is a substring match (use `exact: true`). Test HTML5 drag with `DragEvent`s in SEPARATE `evaluate` calls (dragstart, then drop). PDF gaps are measured per page (`y` restarts). A repeating table header means header-row counts need `>=`. A "no `<option>`" check on the objective picker is checking the old control. A check that reads "nothing paints at the palest token" must walk every element and compare against the browser-resolved token, not a hand-picked label list.
